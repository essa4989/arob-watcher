# 🌸 منصة رعاية عروب — Aroob Care Platform

منصة رعاية منزلية متكاملة ومستقلة تماماً عن Google Sheets/Apps Script، مبنية بنفس فلسفة
ونضج النظام الموصوف في `PROJECT_MASTER_SPEC.md` (v22)، لكن بقاعدة بيانات حقيقية (PostgreSQL)
وخادم Node.js مستقل وواجهة React عصرية.

كل القواعد الطبية والمنطق البرمجي (تصعيد تنبيه القسطرة 90/120/150/180/210 دقيقة، عتبات الحمى
والأكسجين والنبض، نظام التحفيز بعشرة مستويات، الملخص الذكي وكشف الأنماط، الأدوار الثلاثة
وصلاحياتها، سجل التدقيق، وضع النوم، ...) منقولة 1:1 من الوثيقة الأصلية.

## البنية المعمارية

```
arob-watcher/
├── apps/
│   ├── api/    Express + TypeScript + Prisma/PostgreSQL — كل المنطق والـ API والمهام الدورية
│   └── web/    React + TypeScript + Vite — واجهة PWA بثلاث لغات (عربي/إنجليزي/تاغالوغ)
├── packages/
│   └── shared/ ثوابت القواعد الطبية وأنواع TypeScript المشتركة بين الخادم والواجهة
├── docker-compose.yml   PostgreSQL محلي للتطوير
├── Procfile / railway.json   نشر على Railway (خدمة واحدة تخدم API + الواجهة المبنية)
```

خادم Express واحد يخدم كل من `/api/*` والملفات الثابتة لواجهة React المبنية (`apps/web/dist`) —
نفس فكرة الخدمة الواحدة في النظام الأصلي، بدون تكلفة استضافة إضافية.

### لماذا PostgreSQL بدل Google Sheets؟

Sheets كان يحوّل النصوص الشبيهة بالتواريخ تلقائياً وهو ما كسر المؤقت سابقاً — قاعدة بيانات
علائقية حقيقية تحل هذه المشكلة جذرياً بدل الاعتماد على `PropertiesService`. كل حالة كانت تُخزَّن
في Properties (وضع النوم، دورة تنبيه القسطرة، الجلسات، الأسرار) أصبحت أعمدة/جداول حقيقية في
Postgres عبر Prisma، مع الحفاظ على نفس أسلوب `getSetting/setSetting` كطبقة وصول موحدة.

## المزايا المنقولة بالكامل

- تسجيل 5 أنواع (قسطرة، دواء، فحص، سوائل، عناية) + مؤقت حي بـ 5 مستويات تنبيه.
- 12+ نوع إشعار Telegram، بما فيها التنبيهات الحرجة التي لا تتوقف أبداً حتى في وضع النوم.
- نظام تحفيز كامل: 10 مستويات، سلاسل أيام، مكافآت، لوحة شرف.
- ملخص ذكي + كشف 4 أنماط طبية (حمى متكررة، انخفاض بول، بول دموي، رفض سوائل).
- مصادقة PIN بثلاثة أدوار (أب/أم، ممرضة، طبيب) — **مفروضة فعلياً على مستوى الخادم**، وليس
  الواجهة فقط كما كان في النظام السابق (كان هذا أحد نقاط الضعف الموثقة).
- سجل تدقيق كامل، وضع نوم متزامن بين الأجهزة، تراجع/حذف بنافذة 30 دقيقة.
- 3 لغات (عربي RTL / إنجليزي / تاغالوغ)، PWA قابلة للتثبيت، تصدير Excel وPDF.
- جدولة أدوية مع كشف الجرعات الفائتة (>60 دقيقة).
- دعم أطفال متعددين (`childId`) جاهز بنيوياً — طفل واحد افتراضي حالياً (عروب).

## التشغيل محلياً

### المتطلبات
Node.js ≥ 20، وPostgreSQL (عبر Docker أو تثبيت محلي).

### 1) قاعدة البيانات
```bash
docker compose up -d postgres
# أو استخدم أي PostgreSQL محلي/سحابي وحدّث DATABASE_URL في apps/api/.env
```

### 2) متغيرات البيئة
```bash
cp apps/api/.env.example apps/api/.env
# عدّل DATABASE_URL و JWT_SECRET و TELEGRAM_BOT_TOKEN حسب الحاجة
```

### 3) التثبيت والترحيل
```bash
npm install
npm run build:shared
npm run db:migrate --workspace=apps/api
npm run db:seed --workspace=apps/api   # يُنشئ الطفل الافتراضي، الرموز الافتراضية، محادثات Telegram
```

### 4) التشغيل
```bash
npm run dev:api    # الخادم على :8080
npm run dev:web    # الواجهة على :5173 (بروكسي لـ /api على :8080)
```

الرموز الافتراضية عند أول تشغيل (يجب تغييرها من الإعدادات فوراً):

| الدور | PIN |
|-------|:---:|
| parent | 1234 |
| nurse | 5678 |
| doctor | 9999 |

## البناء للإنتاج

```bash
npm run build     # يبني shared ثم api ثم web
npm start         # يشغّل apps/api/dist/index.js — يخدم API + واجهة web المبنية معاً
```

## النشر على Railway

المستودع يحتوي `railway.json` و`Procfile` جاهزين:

1. أنشئ مشروع Railway جديد من هذا المستودع، وأضف قاعدة بيانات PostgreSQL (Railway يوفرها مجاناً).
2. اربط `DATABASE_URL` تلقائياً من إضافة Postgres، وأضف بقية متغيرات البيئة من `.env.example`
   (`JWT_SECRET`, `TELEGRAM_BOT_TOKEN`, ...).
3. Railway يبني بأمر `npm ci && npm run build`، ثم عند كل نشر يشغّل `prisma migrate deploy`
   تلقائياً قبل بدء الخادم (`deploy.startCommand` في `railway.json`).
4. اضبط `TZ` (مثل `Asia/Riyadh`) في متغيرات البيئة لضمان تطابق وضع النوم والتقرير اليومي (23:00)
   مع التوقيت المحلي للعائلة.

## بوت Telegram

النظام يعيد استخدام نفس البوت `@Aruob_bot` ومحادثاته الثلاث (تُزرع تلقائياً عبر `db:seed`).
زوّد `TELEGRAM_BOT_TOKEN` في متغيرات البيئة — لا حاجة لأي إعداد آخر، الإرسال Push مباشر عبر
`UrlFetch`-equivalent (`fetch`) بدون Webhooks أو Polling، بنفس فلسفة النظام الأصلي.

## القواعد الطبية (لا تُغيَّر بدون مراجعة بشرية صريحة)

محفوظة بالكامل في `packages/shared/src/constants.ts` — الفترة المثالية للقسطرة 90 دقيقة،
تصعيد 90/120/150/180/210، بول حرج <30مل، حمى ≥38.5°/≥39°، أكسجين حرج <90%، تسارع نبض >130،
دواء فائت >60 دقيقة. أي تعديل على هذه القيم يجب أن يمر عبر مراجعة صريحة، تماماً كما في الوثيقة
الأصلية.
